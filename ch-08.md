## 第一节 存储方案总览

- 五种存储方式
- 内部存储与外部存储
- 如何选择

---

### Android 的存储方案

| 方案 | 适合数据 | 特点 |
| --- | --- | --- |
| **DataStore** | 用户设置、开关、token | 键值对，异步，取代 SharedPreferences |
| **文件** | 图片、缓存、日志 | 直接读写字节/文本 |
| **Room（SQLite）** | 结构化业务数据 | 支持查询、关系、事务、响应式 |
| **ContentProvider** | 需跨应用共享 | 对外暴露数据 |
| **网络/云端** | 需多端同步 | 依赖网络 |

---

### 内部存储 vs 外部存储

```kotlin
// 内部存储：应用私有，卸载即删除，无需权限
context.filesDir       // /data/data/<包名>/files
context.cacheDir       // /data/data/<包名>/cache（系统空间不足时可能被清理）

// 应用专属外部存储：卸载即删除，无需权限
context.getExternalFilesDir(null)    // /sdcard/Android/data/<包名>/files
context.externalCacheDir

// 共享存储：需通过 MediaStore 或 SAF 访问
MediaStore.Images.Media.EXTERNAL_CONTENT_URI
```

> Android 10+ 启用**分区存储**，不能再随意读写 `/sdcard` 根目录。

---

### 选择决策

```text
数据是简单的配置项？ ──是→ DataStore
        │否
数据是二进制文件或大文本？ ──是→ 文件（内部存储 / 缓存目录）
        │否
数据有结构、需要查询和关联？ ──是→ Room
        │否
需要被其他应用读取？ ──是→ ContentProvider
```

## 第二节 文件存储

- 内部文件读写
- 缓存目录
- 应用专属外部存储

---

### 内部文件读写

```kotlin
// 写
context.openFileOutput("notes.txt", Context.MODE_PRIVATE).use { out ->
    out.write("Hello Android".toByteArray())
}

// 读
val content = context.openFileInput("notes.txt").bufferedReader().use { it.readText() }

// Kotlin 扩展写法
File(context.filesDir, "notes.txt").writeText("Hello")
val text = File(context.filesDir, "notes.txt").readText()

// 列出与删除
context.fileList()
context.deleteFile("notes.txt")
```

> `use {}` 自动关闭流，等价于 Java 的 try-with-resources。

---

### 文件操作要放在 IO 线程

```kotlin
class FileRepository(private val context: Context) {

    suspend fun save(name: String, content: String) = withContext(Dispatchers.IO) {
        File(context.filesDir, name).writeText(content)
    }

    suspend fun load(name: String): String = withContext(Dispatchers.IO) {
        val f = File(context.filesDir, name)
        if (f.exists()) f.readText() else ""
    }
}
```

> 在主线程做 IO 会触发 ANR。**所有磁盘/网络操作都必须切到 `Dispatchers.IO`。**

---

### 缓存目录

```kotlin
// 缓存：可被系统清理，不要放重要数据
val cacheFile = File(context.cacheDir, "temp_image.jpg")

// 清理缓存
context.cacheDir.deleteRecursively()

// 计算缓存大小
fun File.sizeInMb(): Double =
    walkTopDown().filter { it.isFile }.sumOf { it.length() } / 1024.0 / 1024.0
```

> 应用应在设置页提供"清除缓存"入口，这是国内应用商店的常见审核项。

## 第三节 DataStore 键值存储

- 为什么替代 SharedPreferences
- Preferences DataStore
- 读写与观察

---

### SharedPreferences 的问题

```kotlin
// 旧方式
val sp = context.getSharedPreferences("config", Context.MODE_PRIVATE)
sp.edit().putString("token", "abc").apply()
val token = sp.getString("token", "")     // 主线程同步读，首次加载可能阻塞
```

问题：

- `apply()` 异步写但**首次读是同步的**，可能阻塞主线程造成 ANR
- 没有错误处理机制
- 不支持事务，不是响应式

---

### Preferences DataStore

```kotlin
// build.gradle.kts
implementation("androidx.datastore:datastore-preferences:1.1.1")
```

```kotlin
// 顶层声明，整个进程唯一
val Context.dataStore: DataStore<Preferences> by preferencesDataStore(name = "settings")

object PrefKeys {
    val USER_NAME = stringPreferencesKey("user_name")
    val DARK_MODE = booleanPreferencesKey("dark_mode")
    val FONT_SIZE = intPreferencesKey("font_size")
}
```

---

### 读写 DataStore

```kotlin
class SettingsRepository(private val context: Context) {

    // 读：返回 Flow，值变化时自动发射
    val darkMode: Flow<Boolean> = context.dataStore.data
        .catch { e -> if (e is IOException) emit(emptyPreferences()) else throw e }
        .map { prefs -> prefs[PrefKeys.DARK_MODE] ?: false }

    // 写：挂起函数，事务性
    suspend fun setDarkMode(enabled: Boolean) {
        context.dataStore.edit { prefs ->
            prefs[PrefKeys.DARK_MODE] = enabled
        }
    }
}
```

---

### 在 UI 中使用

```kotlin
class SettingsViewModel(private val repo: SettingsRepository) : ViewModel() {
    val darkMode = repo.darkMode
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), false)

    fun toggleDarkMode(v: Boolean) = viewModelScope.launch { repo.setDarkMode(v) }
}
```

```kotlin
@Composable
fun SettingsScreen(vm: SettingsViewModel = viewModel()) {
    val dark by vm.darkMode.collectAsStateWithLifecycle()
    Row(verticalAlignment = Alignment.CenterVertically) {
        Text("深色模式", Modifier.weight(1f))
        Switch(checked = dark, onCheckedChange = vm::toggleDarkMode)
    }
}
```

## 第四节 Room 数据库基础

### Room 架构

```text
        ┌─────────────────────────────────┐
        │          Repository             │
        └────────────────┬────────────────┘
                         ↓
        ┌─────────────────────────────────┐
        │      Database (RoomDatabase)     │
        │   ┌─────────────────────────┐    │
        │   │   DAO（数据访问对象）      │    │
        │   └─────────────────────────┘    │
        │   ┌─────────────────────────┐    │
        │   │   Entity（表结构）        │    │
        │   └─────────────────────────┘    │
        └─────────────────────────────────┘
                         ↓
                    SQLite 文件
```

Room 是 SQLite 之上的抽象层，**在编译期检查 SQL 语句**。

---

### 依赖配置

```kotlin
// build.gradle.kts (模块)
plugins {
    alias(libs.plugins.ksp)          // Kotlin Symbol Processing
}

dependencies {
    val room = "2.6.1"
    implementation("androidx.room:room-runtime:$room")
    implementation("androidx.room:room-ktx:$room")      // 协程与 Flow 支持
    ksp("androidx.room:room-compiler:$room")
}
```

> KSP 比 KAPT 编译更快，新项目一律用 KSP。

---

### Entity：定义表

```kotlin
@Entity(tableName = "todos")
data class TodoEntity(
    @PrimaryKey(autoGenerate = true)
    val id: Long = 0,

    @ColumnInfo(name = "title")
    val title: String,

    val done: Boolean = false,

    @ColumnInfo(name = "created_at")
    val createdAt: Long = System.currentTimeMillis(),

    @ColumnInfo(index = true)
    val categoryId: Long? = null
)
```

- 类名 → 表名，属性 → 列，必须有主键
- 复合主键：`@Entity(primaryKeys = ["a", "b"])`

---

### Database

```kotlin
@Database(
    entities = [TodoEntity::class, CategoryEntity::class],
    version = 1,
    exportSchema = true
)
abstract class AppDatabase : RoomDatabase() {
    abstract fun todoDao(): TodoDao

    companion object {
        @Volatile private var INSTANCE: AppDatabase? = null

        fun getInstance(context: Context): AppDatabase =
            INSTANCE ?: synchronized(this) {
                INSTANCE ?: Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "app.db"
                ).build().also { INSTANCE = it }
            }
    }
}
```

> 数据库实例应为**单例**：每次 `databaseBuilder` 都会新建连接池，开销很大。

### DAO 基本操作

```kotlin
@Dao
interface TodoDao {

    @Query("SELECT * FROM todos ORDER BY created_at DESC")
    fun observeAll(): Flow<List<TodoEntity>>          // 响应式，数据变化自动发射

    @Query("SELECT * FROM todos WHERE id = :id")
    suspend fun getById(id: Long): TodoEntity?

    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(todo: TodoEntity): Long

    @Update
    suspend fun update(todo: TodoEntity)

    @Delete
    suspend fun delete(todo: TodoEntity)

    @Query("DELETE FROM todos WHERE done = 1")
    suspend fun deleteCompleted(): Int
}
```

---

### 返回 Flow 的威力

```kotlin
@Query("SELECT * FROM todos WHERE done = :done")
fun observeByStatus(done: Boolean): Flow<List<TodoEntity>>
```

```kotlin
class TodoViewModel(private val repo: TodoRepository) : ViewModel() {
    val uiState: StateFlow<TodoUiState> = repo.observeAll()
        .map { TodoUiState(items = it, isLoading = false) }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), TodoUiState(isLoading = true))
}
```

> 插入一条数据 → Room 自动发射新列表 → UI 自动刷新。**不需要手动刷新列表**。

---

### 复杂查询

```kotlin
@Dao
interface TodoDao {
    @Query("SELECT * FROM todos WHERE title LIKE '%' || :keyword || '%'")
    fun search(keyword: String): Flow<List<TodoEntity>>

    @Query("SELECT COUNT(*) FROM todos WHERE done = 0")
    fun countPending(): Flow<Int>

    @Query("SELECT * FROM todos WHERE created_at BETWEEN :start AND :end")
    suspend fun getByDateRange(start: Long, end: Long): List<TodoEntity>

    @Query("SELECT * FROM todos WHERE id IN (:ids)")
    suspend fun getByIds(ids: List<Long>): List<TodoEntity>

    @Query("SELECT * FROM todos LIMIT :limit OFFSET :offset")
    suspend fun getPage(limit: Int, offset: Int): List<TodoEntity>
}
```

> SQL 写错时**编译就会报错**，这是 Room 相对裸 SQLite 的最大优势。

---

### 关系查询

```kotlin
@Entity(tableName = "categories")
data class CategoryEntity(@PrimaryKey val id: Long, val name: String)

// 一对多
data class CategoryWithTodos(
    @Embedded val category: CategoryEntity,
    @Relation(parentColumn = "id", entityColumn = "categoryId")
    val todos: List<TodoEntity>
)

@Dao
interface CategoryDao {
    @Transaction
    @Query("SELECT * FROM categories")
    fun observeAllWithTodos(): Flow<List<CategoryWithTodos>>
}
```

### 事务

```kotlin
@Dao
interface TodoDao {
    @Transaction
    suspend fun replaceAll(todos: List<TodoEntity>) {
        deleteAll()
        insertAll(todos)
    }
}
```

```kotlin
// 或在 Database 层面
db.withTransaction {
    todoDao.deleteAll()
    todoDao.insertAll(newList)
}
```

> 事务保证多个操作**要么全部成功，要么全部回滚**。

### 类型转换器

```kotlin
class Converters {
    @TypeConverter
    fun fromTimestamp(value: Long?): Date? = value?.let { Date(it) }

    @TypeConverter
    fun dateToTimestamp(date: Date?): Long? = date?.time

    @TypeConverter
    fun fromStringList(value: String): List<String> =

    fun toStringList(list: List<String>): String = list.joinToString(",")
```

### Repository 封装

```kotlin
class TodoRepository(private val dao: TodoDao) {

    fun observeAll(): Flow<List<Todo>> =
        dao.observeAll().map { list -> list.map { it.toDomain() } }

    suspend fun add(title: String) {
        dao.insert(TodoEntity(title = title))
    }

    suspend fun toggle(todo: Todo) {
        dao.update(todo.toEntity().copy(done = !todo.done))
    }
}

// 实体与领域模型的映射
fun TodoEntity.toDomain() = Todo(id, title, done, createdAt)
fun Todo.toEntity() = TodoEntity(id, title, done, createdAt)
```

> Repository 屏蔽数据来源（本地/网络），上层只面对领域模型。

---

### 数据库迁移

```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(db: SupportSQLiteDatabase) {
        db.execSQL("ALTER TABLE todos ADD COLUMN priority INTEGER NOT NULL DEFAULT 0")
    }
}

Room.databaseBuilder(context, AppDatabase::class.java, "app.db")
    .addMigrations(MIGRATION_1_2)
    .build()
```

```kotlin
// 开发阶段的偷懒方式：破坏性迁移（清空数据！仅限开发期）
.fallbackToDestructiveMigration()
```

> 改了 Entity 而没升 `version` 并提供迁移，运行时会直接崩溃。

## 本章小结

- 配置项用 **DataStore**，文件用内部存储，结构化数据用 **Room**
- 一切磁盘操作必须在 `Dispatchers.IO`，主线程 IO 会导致 ANR
- Room 三件套：`@Entity` 定义表、`@Dao` 定义操作、`@Database` 组装
- DAO 返回 `Flow` 即可获得**自动刷新**的响应式列表
- 修改表结构必须升 `version` 并提供 `Migration`
