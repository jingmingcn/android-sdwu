### 异步编程的演进

```kotlin
// 回调地狱
api.getUser(id) { user ->
    api.getPosts(user.id) { posts ->
        api.getComments(posts[0].id) { comments ->
            runOnUiThread { render(comments) }      // 层层嵌套，错误处理困难
        }
    }
}
```

```kotlin
// 协程：像同步代码一样直观
viewModelScope.launch {
    val user = api.getUser(id)
    val posts = api.getPosts(user.id)
    val comments = api.getComments(posts[0].id)
    render(comments)
}
```

---

### 协程是什么

> 协程是**可挂起的计算**：能在某处暂停，稍后在同一或不同线程恢复，而**不阻塞线程**。

```text
线程阻塞：  线程 ──[等待网络 2 秒，什么也不干]── 继续
协程挂起：  线程 ──[挂起，去执行别的任务]──── 恢复
```

- 一个线程可以承载**成千上万**个协程
- 挂起是**编译器实现**的（状态机 + Continuation），不是操作系统特性

---

### 挂起函数

```kotlin
suspend fun fetchUser(id: Int): User {
    delay(1000)                      // 挂起，不阻塞线程
    return api.getUser(id)
}
```

- `suspend` 只能在**协程**或**另一个挂起函数**中调用
- `suspend` 本身不改变线程，只是标记"这里可能挂起"
- 编译器为其生成状态机，`delay` 与 `Thread.sleep` 有本质区别

```kotlin
// ✗ Thread.sleep 阻塞整个线程
// ✓ delay 只挂起当前协程
```

---

### 启动协程

```kotlin
// Android 中最常用的三个作用域
viewModelScope.launch { }        // ViewModel 销毁时取消
lifecycleScope.launch { }        // Activity/Fragment 销毁时取消
rememberCoroutineScope()         // Compose 离开组合时取消

// 测试与顶层入口
runBlocking { }                  // 阻塞当前线程，仅用于测试和 main 函数

// 自建作用域（需自己管理取消）
val scope = CoroutineScope(SupervisorJob() + Dispatchers.Main)
scope.cancel()
```

> **绝不要**用 `GlobalScope`：它不受任何生命周期约束，是内存泄漏的常见来源。

### async 与并发

```kotlin
// 串行：总耗时 = t1 + t2
suspend fun loadSerial() {
    val user = fetchUser()        // 1 秒
    val posts = fetchPosts()      // 1 秒
}                                 // 共 2 秒

// 并发：总耗时 = max(t1, t2)
suspend fun loadParallel() = coroutineScope {
    val userDeferred = async { fetchUser() }
    val postsDeferred = async { fetchPosts() }
    val user = userDeferred.await()
    val posts = postsDeferred.await()
}                                 // 共 1 秒
```

| | 返回值 |
| --- | --- |
| `launch` | `Job`，只管执行 |
| `async` | `Deferred<T>`，可 `await()` 拿结果 |

## 第二节 调度器与结构化并发

---

### 调度器（Dispatcher）

| 调度器 | 线程池 | 用途 |
| --- | --- | --- |
| `Dispatchers.Main` | 主线程 | 更新 UI |
| `Dispatchers.IO` | 弹性线程池 | 网络、数据库、文件 |
| `Dispatchers.Default` | CPU 核数 | 排序、解析、计算 |
| `Dispatchers.Unconfined` | 不限定 | 极少使用 |

```kotlin
viewModelScope.launch {                     // 默认 Main
    val data = withContext(Dispatchers.IO) { // 切到 IO
        repository.loadFromNetwork()
    }
    uiState = data                           // 回到 Main
}
```

---

### 主线程安全

```kotlin
// ✓ 挂起函数应自己保证主线程安全，调用方无需关心
class UserRepository(private val api: ApiService) {
    suspend fun getUser(id: Int): User = withContext(Dispatchers.IO) {
        api.getUser(id)
    }
}

// 调用方直接调用，不必写 withContext
viewModelScope.launch {
    val user = repository.getUser(1)
}
```

> **原则**：谁做耗时操作，谁负责切线程。Retrofit 和 Room 的挂起函数已内置主线程安全。

---

### 结构化并发

```kotlin
viewModelScope.launch {          // 父协程
    launch { taskA() }           // 子协程 1
    launch { taskB() }           // 子协程 2
}                                // 父协程等待所有子协程完成
```

三条规则：

1. 父协程取消 → **所有子协程自动取消**
2. 子协程异常 → 默认**取消父协程和所有兄弟协程**
3. 父协程等待所有子协程完成后才算完成

> 这消灭了"忘记取消导致的泄漏"这一类问题。

---

### 取消与超时

```kotlin
val job = viewModelScope.launch { longTask() }
job.cancel()                     // 取消

// 协程取消是协作式的：必须检查取消状态
suspend fun longTask() {
    repeat(1000) { i ->
        ensureActive()           // 或 if (!isActive) return
        heavyCompute(i)
    }
}

// 超时
withTimeout(5000) { fetchData() }              // 超时抛 TimeoutCancellationException
val r = withTimeoutOrNull(5000) { fetchData() } // 超时返回 null
```

---

### 异常处理

```kotlin
// 1. try-catch（推荐用于具体的挂起调用）
viewModelScope.launch {
    try {
        val user = repository.getUser(id)
        _uiState.update { it.copy(user = user) }
    } catch (e: IOException) {
        _uiState.update { it.copy(error = "网络异常") }
    }
}

// 2. runCatching
val result = runCatching { repository.getUser(id) }
result.onSuccess { }.onFailure { }

// 3. CoroutineExceptionHandler（顶层兜底）
val handler = CoroutineExceptionHandler { _, e -> Log.e(TAG, "未捕获", e) }
viewModelScope.launch(handler) { }
```

> 注意：`CancellationException` 是正常取消信号，**不要**捕获后吞掉。

---

### SupervisorJob

```kotlin
// 普通 Job：一个子协程失败，兄弟全部被取消
coroutineScope {
    launch { throw IOException() }
    launch { taskB() }              // 被取消
}

// SupervisorJob：子协程互相独立
supervisorScope {
    launch { throw IOException() }
    launch { taskB() }              // 继续执行
}
```

> `viewModelScope` 内部就用了 `SupervisorJob`。

## 第三节 Flow 数据流

- Flow 基础
- 常用操作符
- StateFlow 与 SharedFlow
- 冷流与热流

---

### Flow 基础

```kotlin
fun countdown(from: Int): Flow<Int> = flow {
    for (i in from downTo 0) {
        emit(i)                     // 发射值
        delay(1000)
    }
}

viewModelScope.launch {
    countdown(5).collect { value ->  // 收集值
        println(value)
    }
}
```

- **冷流**：只有被 `collect` 时才开始执行，每个收集者独立执行一遍
- 挂起函数返回**一个**值，Flow 返回**多个**值

---

### 常用操作符

```kotlin
flow
    .map { it * 2 }
    .filter { it > 10 }
    .take(5)
    .onEach { Log.d(TAG, "值：$it") }
    .distinctUntilChanged()
    .debounce(300)                     // 防抖：搜索框输入常用
    .flowOn(Dispatchers.IO)            // 指定上游执行的调度器
    .catch { e -> emit(fallback) }     // 捕获上游异常
    .onStart { showLoading() }
    .onCompletion { hideLoading() }
    .collect { render(it) }
```

```kotlin
// 组合多个流
combine(flowA, flowB) { a, b -> a + b }
flowA.zip(flowB) { a, b -> a to b }
flowA.flatMapLatest { query -> repository.search(query) }   // 新值到达即取消旧任务
```

---

### 搜索场景的经典组合

```kotlin
class SearchViewModel(private val repo: Repo) : ViewModel() {
    private val query = MutableStateFlow("")

    @OptIn(ExperimentalCoroutinesApi::class)
    val results: StateFlow<List<Item>> = query
        .debounce(300)                          // 停止输入 300ms 后才搜索
        .filter { it.length >= 2 }              // 至少 2 个字符
        .distinctUntilChanged()                 // 内容没变不重复搜索
        .flatMapLatest { repo.search(it) }      // 新搜索取消旧搜索
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), emptyList())

    fun onQueryChange(q: String) { query.value = q }
}
```

---

### StateFlow 与 SharedFlow

| | StateFlow | SharedFlow |
| --- | --- | --- |
| 初始值 | 必须有 | 没有 |
| 保留最新值 | 是 | 可配置 `replay` |
| 去重 | 自动去重 | 不去重 |
| 用途 | **UI 状态** | **一次性事件** |

```kotlin
private val _uiState = MutableStateFlow(UiState())
val uiState: StateFlow<UiState> = _uiState.asStateFlow()

private val _events = MutableSharedFlow<UiEvent>()
val events: SharedFlow<UiEvent> = _events.asSharedFlow()
```

---

### 冷流转热流

```kotlin
val uiState: StateFlow<UiState> = repository.observeAll()   // 冷流（Room）
    .map { UiState(items = it) }
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5_000),    // 无订阅者 5 秒后停止
        initialValue = UiState(isLoading = true)
    )
```

`SharingStarted` 三种策略：

- `Eagerly`：立即开始，直到作用域结束
- `Lazily`：首个订阅者到达时开始，之后一直保持
- `WhileSubscribed(5_000)`：**推荐**，旋转屏幕期间不重启上游

interface GitHubApi {

    @GET("users/{login}")
    suspend fun getUser(@Path("login") login: String): UserDto

    @GET("search/repositories")
    suspend fun searchRepos(
        @Query("q") query: String,

// 统一添加 Token
class AuthInterceptor(private val tokenProvider: () -> String?) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val token = tokenProvider()
        val request = chain.request().newBuilder().apply {
            token?.let { addHeader("Authorization", "Bearer $it") }

### DTO 与领域模型分离

```kotlin
// 网络层：DTO，字段与接口一一对应
@Serializable
data class UserDto(val id: Long, val login: String, @SerialName("avatar_url") val avatarUrl: String)

// 业务层：领域模型，只保留应用关心的字段
data class User(val id: Long, val name: String, val avatar: String)

fun UserDto.toDomain() = User(id = id, name = name ?: login, avatar = avatarUrl)
```

> 好处：后端字段变更只影响 DTO 和一个映射函数，不会扩散到整个应用。

### 统一结果封装

```kotlin
sealed interface NetworkResult<out T> {
    data class Success<T>(val data: T) : NetworkResult<T>
    data class Error(val code: Int?, val message: String) : NetworkResult<Nothing>
    data object Loading : NetworkResult<Nothing>
}

suspend fun <T> safeApiCall(block: suspend () -> T): NetworkResult<T> = try {
    NetworkResult.Success(block())
} catch (e: CancellationException) {
    throw e                                           // 取消要向上传播
} catch (e: HttpException) {
    NetworkResult.Error(e.code(), "服务器错误：${e.code()}")
} catch (e: IOException) {
    NetworkResult.Error(null, "网络连接失败，请检查网络")
} catch (e: Exception) {
    NetworkResult.Error(null, e.message ?: "未知错误")
}
```

### 在 ViewModel 中使用

```kotlin
class RepoViewModel(private val repo: RepoRepository) : ViewModel() {
    private val _uiState = MutableStateFlow(RepoUiState())
    val uiState = _uiState.asStateFlow()

    fun search(query: String) {
        viewModelScope.launch {
            _uiState.update { it.copy(isLoading = true, error = null) }
            when (val r = repo.search(query)) {
                is NetworkResult.Success ->
                    _uiState.update { it.copy(items = r.data, isLoading = false) }
                is NetworkResult.Error ->
                    _uiState.update { it.copy(error = r.message, isLoading = false) }
                NetworkResult.Loading -> Unit
            }
        }
    }
}
```

### 离线优先架构

```kotlin
class NewsRepository(private val api: NewsApi, private val dao: NewsDao) {

    // 数据库是唯一可信来源，UI 只观察数据库
    fun observeNews(): Flow<List<News>> = dao.observeAll().map { it.map(NewsEntity::toDomain) }

    // 刷新：拉网络 → 写数据库 → Flow 自动推送新数据给 UI
    suspend fun refresh(): NetworkResult<Unit> = safeApiCall {
        val remote = api.getNews()
        dao.replaceAll(remote.map { it.toEntity() })
    }
}
```

> **Single Source of Truth**：网络只负责更新数据库，UI 永远只读数据库。断网时应用仍可用。

## 本章小结

- 协程用**挂起**代替阻塞；`launch` 执行任务，`async` 并发取结果
- `Dispatchers.IO` 做网络与磁盘，`Main` 更新 UI；挂起函数自己保证主线程安全
- 结构化并发让取消自动向下传播；永远不要用 `GlobalScope`
- `Flow` 表达多值异步流；`StateFlow` 存 UI 状态，`SharedFlow` 传一次性事件
- Retrofit + kotlinx.serialization 是现代网络栈；DTO 与领域模型要分离
