## 第一节 ViewModel 详解

- ViewModel 的职责
- 生命周期与作用域
- viewModelScope
- SavedStateHandle

---

### ViewModel 解决什么问题

```text
        屏幕旋转
Activity ────────→ 销毁重建 ────→ UI 状态丢失、网络请求重发
   │
   └── ViewModel ─────────────────→ 存活，状态保留
                （直到 Activity 真正结束）
```

职责：

- 持有并管理**屏幕级 UI 状态**
- 处理 UI 事件、调用业务逻辑（Repository）
- **不持有** View / Context / Activity 引用（否则内存泄漏）

---

### ViewModel 的生命周期

```text
Activity 生命周期：  创建 ──旋转──重建 ──旋转──重建 ── finish()
ViewModel 生命周期： ├────────────────────────────────┤ onCleared()
```

- 由 `ViewModelStoreOwner`（Activity / Fragment / NavBackStackEntry）持有
- 配置变更时保留；宿主真正销毁时调用 `onCleared()`

```kotlin
class MyViewModel : ViewModel() {
    override fun onCleared() {
        super.onCleared()
        // 释放资源（viewModelScope 会自动取消，无需手动处理）
    }
}
```

### viewModelScope

```kotlin
class UserViewModel(private val repo: UserRepository) : ViewModel() {
    private val _uiState = MutableStateFlow(UserUiState())
    val uiState = _uiState.asStateFlow()

    fun load(id: Int) {
        viewModelScope.launch {                     // ViewModel 销毁时自动取消
            _uiState.update { it.copy(isLoading = true) }
            runCatching { repo.getUser(id) }
                .onSuccess { u -> _uiState.update { it.copy(user = u, isLoading = false) } }
                .onFailure { e -> _uiState.update { it.copy(error = e.message, isLoading = false) } }
        }
    }
}
```

### SavedStateHandle

```kotlin
class SearchViewModel(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {

    // 进程被杀后重建仍能恢复
    var query: String
        get() = savedStateHandle["query"] ?: ""
        set(value) { savedStateHandle["query"] = value }

    // 也可以直接取导航参数
    private val userId: Int = checkNotNull(savedStateHandle["userId"])

    val queryFlow: StateFlow<String> =
        savedStateHandle.getStateFlow("query", "")
}
```

> ViewModel 抗**配置变更**，SavedStateHandle 抗**进程被杀**，两者互补。

---

### StateFlow 的正确收集方式

```kotlin
// ✓ 推荐：界面不可见时自动停止收集，省电
val uiState by viewModel.uiState.collectAsStateWithLifecycle()

// ✗ 不推荐：即便应用退到后台仍在收集
val uiState by viewModel.uiState.collectAsState()
```

依赖：`androidx.lifecycle:lifecycle-runtime-compose`

| 类型 | 特点 |
| --- | --- |
| `StateFlow` | 有初始值、有当前值、去重，适合 UI 状态 |
| `SharedFlow` | 无初始值，适合一次性事件（导航、Toast） |

### 核心概念

| 概念 | 说明 |
| --- | --- |
| `NavController` | 导航的控制器，执行跳转和返回 |
| `NavHost` | 承载当前页面的容器，声明路由图 |
| `NavGraph` | 所有目的地的集合 |
| 目的地（destination） | 一个可组合页面 |
| 返回栈（back stack） | 已访问页面的栈 |

```kotlin
dependencies {
    implementation("androidx.navigation:navigation-compose:2.8.0")
}
```

---

### 定义路由

```kotlin
// 用密封类定义类型安全的路由
sealed class Screen(val route: String) {
    data object Home : Screen("home")
    data object Profile : Screen("profile")
    data object Detail : Screen("detail/{itemId}") {
        fun createRoute(itemId: Int) = "detail/$itemId"
    }
}
```

> 避免在跳转处直接写字符串字面量，否则拼错只有运行时才发现。

---

### NavHost

```kotlin
@Composable
fun AppNavHost() {
    val navController = rememberNavController()

    NavHost(
        navController = navController,
        startDestination = Screen.Home.route
    ) {
        composable(Screen.Home.route) {
            HomeScreen(onItemClick = { id ->
                navController.navigate(Screen.Detail.createRoute(id))
            })
        }
        composable(Screen.Profile.route) { ProfileScreen() }
        composable(
            route = Screen.Detail.route,
            arguments = listOf(navArgument("itemId") { type = NavType.IntType })
        ) { backStackEntry ->
            val id = backStackEntry.arguments?.getInt("itemId") ?: 0
            DetailScreen(itemId = id, onBack = { navController.popBackStack() })
        }
    }
}
```

---

### 导航操作

```kotlin
navController.navigate("detail/1")             // 前进
navController.popBackStack()                   // 返回上一页
navController.navigateUp()                     // 向上（含深链接处理）

// 返回到指定页面
navController.popBackStack(Screen.Home.route, inclusive = false)

// 登录成功后跳首页，且不允许返回登录页
navController.navigate(Screen.Home.route) {
    popUpTo(Screen.Login.route) { inclusive = true }
}

// 避免重复点击产生多个相同页面
navController.navigate(route) { launchSingleTop = true }
```

---

### 页面应保持"可导航无关"

```kotlin
// ✓ 好：页面只暴露事件，不知道 NavController 的存在
@Composable
fun HomeScreen(onItemClick: (Int) -> Unit, onProfileClick: () -> Unit) { /* ... */ }

// ✗ 差：页面直接依赖 NavController，无法单独预览和测试
@Composable
fun HomeScreen(navController: NavController) { /* ... */ }
```

> 导航逻辑集中在 `NavHost` 中，页面组件保持纯粹。

### 在 ViewModel 中直接取参数

```kotlin
class DetailViewModel(savedStateHandle: SavedStateHandle) : ViewModel() {
    private val itemId: Int = checkNotNull(savedStateHandle["itemId"])

    val uiState = repository.observeItem(itemId)
        .map { DetailUiState(item = it) }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), DetailUiState())
}
```

> 导航参数会自动进入 `SavedStateHandle`，页面组件无需再往下透传。

---

### 传递复杂对象的原则

```kotlin
// ✗ 不要在路由中传整个对象（序列化到 URL，易出错、有长度限制）
navController.navigate("detail/${Json.encodeToString(user)}")

// ✓ 只传 ID，详情页自己去仓库取
navController.navigate("detail/${user.id}")
```

> 路由是"地址"，不是"数据通道"。深链接与进程重建时，只有 ID 才可靠。

### 底部导航栏

```kotlin
@Composable
fun MainScreen() {
    val navController = rememberNavController()
    val items = listOf(Screen.Home, Screen.Discover, Screen.Mine)

    Scaffold(
        bottomBar = {
            NavigationBar {
                val backStackEntry by navController.currentBackStackEntryAsState()
                val currentRoute = backStackEntry?.destination?.route

                items.forEach { screen ->
                    NavigationBarItem(
                        selected = currentRoute == screen.route,
                        onClick = { navController.navigateToTab(screen.route) },
                        icon = { Icon(screen.icon, null) },
                        label = { Text(screen.label) }
                    )
                }
            }
        }
    ) { padding ->
        AppNavHost(navController, Modifier.padding(padding))
    }
}
```

### 标签页切换的正确姿势

```kotlin
fun NavController.navigateToTab(route: String) {
    navigate(route) {
        // 弹出到起始目的地，避免返回栈无限增长
        popUpTo(graph.findStartDestination().id) {
            saveState = true          // 保存被弹出页面的状态
        }
        launchSingleTop = true        // 避免重复实例
        restoreState = true           // 恢复之前保存的状态
    }
}
```

> 少了 `saveState` / `restoreState`，切回标签页时列表滚动位置会丢失。

## 第五节 生命周期感知

- Lifecycle 与观察

---

### 观察生命周期事件

```kotlin
@Composable
fun LifecycleAwareScreen(onResume: () -> Unit) {
    val lifecycleOwner = LocalLifecycleOwner.current

    DisposableEffect(lifecycleOwner) {
        val observer = LifecycleEventObserver { _, event ->
            when (event) {
                Lifecycle.Event.ON_RESUME -> onResume()
                Lifecycle.Event.ON_PAUSE -> { /* 暂停播放 */ }
                else -> Unit
            }
        }
        lifecycleOwner.lifecycle.addObserver(observer)
        onDispose { lifecycleOwner.lifecycle.removeObserver(observer) }
    }
}
```

---

### repeatOnLifecycle

```kotlin
// 只在界面至少 STARTED 时收集，退到后台自动停止
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.uiState.collect { render(it) }
    }
}
```

在 Compose 中等价于：

```kotlin
val uiState by viewModel.uiState.collectAsStateWithLifecycle()
```

> 忘了做生命周期感知，最典型的后果是**后台耗电**和**已销毁界面更新导致崩溃**。

---

### 一次性事件的处理

```kotlin
// ViewModel 中
private val _events = Channel<UiEvent>()
val events = _events.receiveAsFlow()

fun onSaveClick() = viewModelScope.launch {
    repo.save()
    _events.send(UiEvent.ShowSnackbar("保存成功"))
}
```

```kotlin
// UI 中
LaunchedEffect(Unit) {
    viewModel.events.collect { event ->
        when (event) {
            is UiEvent.ShowSnackbar -> snackbarHostState.showSnackbar(event.msg)
            is UiEvent.NavigateBack -> navController.popBackStack()
        }
    }
}
```

> 用 `StateFlow` 表达一次性事件会在旋转屏幕后**重复触发**，这是常见 bug。

## 本章小结

- ViewModel 承载屏幕级状态，抗配置变更；`SavedStateHandle` 抗进程被杀
- `viewModelScope` 让协程随 ViewModel 自动取消
- Navigation Compose 用 `NavHost` + 路由字符串组织页面；页面组件不应依赖 `NavController`
- 路由只传 ID，不传对象
- 用 `collectAsStateWithLifecycle` 收集状态；一次性事件用 `Channel`，不要用 `StateFlow`
